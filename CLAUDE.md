# Project Rules — Dr. Merve Zeybek Website Rebuild

These rules are permanent and apply to all work on this project unless a specific, approved task explicitly overrides one of them.

1. Never modify unrelated files.
2. Never make product, legal, medical or visual decisions without an approved task brief.
3. Never invent credentials, qualifications, treatment outcomes, statistics, testimonials, prices or health claims.
4. Do not use the current legacy images unless a later task explicitly approves a specific asset.
5. Do not introduce dependencies without explaining why they are required.
6. Use TypeScript strictly.
7. Prefer server components unless client-side interactivity is genuinely required.
8. Preserve accessibility and semantic HTML.
9. All interactive controls require keyboard and visible focus support.
10. The website must be responsive.
11. Do not send personal or health information to analytics.
12. Do not add Google Ads, remarketing or advertising claims without a separate approved legal task.
13. Do not expose secrets in client-side code.
14. Every implementation task must end with lint, TypeScript validation and production build checks.
15. Every response must list changed files, commands executed, tests performed and remaining issues.
16. Do not commit or push unless a task explicitly requests it.
